# Plugin Store promo images

Marketing images for the PWA listing on the Craft Plugin Store, rendered in the same theme as the
plugin's marketing page at
[justinholt.com/plugins/craft-pwa](https://justinholt.com/plugins/craft-pwa).

## Building

```bash
./build.sh          # all slides
./build.sh "2 5"    # just slides 2 and 5
```

Output lands in `out/` as `pwa-promo-N.jpg`, 1920×1080. Headless Chrome renders each slide at 2×
and can only write PNG, so `build.sh` downsamples and converts to JPEG in one `sips` pass and
deletes the PNG. **Promos are JPEG, never PNG** — check `out/` holds only `.jpg` files.

## Screenshots

`shots/` holds real captures from the shared plugin-testing harness (Craft 5, PWA on Pro, two
sites). The demo manifest there is "Orbit Supply Co." with `brand-mark-square.png` as its icon
source; the second site was deliberately left without one, which is what slide 2's failing report
shows.

- `pwa-preflight-blocked.png`, `pwa-preflight.png`, `pwa-flight-plan.png`, `pwa-broadcast.png` —
  `#main` captures from `~/Sites/plugin-shots/capture.mjs` (puppeteer, deviceScaleFactor 2) at a
  1300px viewport (1500px for the flight plan, whose table overflows narrower).
- `pwa-prompt.png`, `pwa-phone-ios.png` — the front end. The Chrome prompt is the plugin's own
  markup, raised by dispatching a `beforeinstallprompt` event, because headless Chrome never fires a
  real one; the iOS shot is a Safari user agent at 393×852. Other plugins' banners (Blaster, Leads)
  were hidden by exact id/class first.
- `generated/` — files copied straight out of the harness's `web/pwa/icons/<site-uid>/`, i.e. what
  the plugin wrote from that one source image.

**Crop in CSS, not in the file.** Each control-panel crop is a `.crop` with `--W` (the capture's
width in CSS px), `--x`, `--y`, `--w`, `--h` (the region, in the same units) and `--s` (scale).
Retaking a screenshot means adjusting those numbers, never recutting a PNG.

## Editing

Everything lives in `slides.html` — one `<section class="slide">` per image. The palette is the
plugin's: accent `#4444C8`, with `#8a8af7` and `#6fd6ff` as highlights. Jersey 20 for display,
Inter for body.

`assets/` holds the fonts, Justin's original icon art (`icon-source.jpg`), and two SVGs:

- `icon.svg` — the app icon, used for the cover mark and the footer lockup. A byte-identical copy
  of `../src/icon.svg`; copy it again whenever the icon changes.
- `watermark.svg` — the install arrow only. The tile, the phone and the plus are stripped: at
  watermark scale the tile and the phone's 4.5-unit outline read as hard-edged boxes across the
  slide, and the plus as a block behind the headings. The arrow's tail runs past the bottom of the
  viewBox, and the slides place the watermark so that cut falls below the slide.

`fonts.css` is generated by `build.sh` (the woff2 files are base64-inlined so Chrome's `file://`
origin rules can't block them) and is not checked in.
